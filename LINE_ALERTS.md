# LINE stock alerts

The `LINE stock alerts` workflow runs after each successful `Refresh Top 10 board (30 minutes)` run on `main`. GitHub scheduling can be delayed; this is not a real-time trade execution service. It reads the published Top 10 board and calls the existing `ranking_policy.is_entry` checklist again at delivery time. It never places orders or changes ranking scores.

Only current, confirmed entries can notify: score at least 80 with full scoring coverage, quote in the entry zone, current reward/risk at least 2, the existing spread/fundamental checks, ranking no older than 35 minutes, quote no older than 15 minutes, and no future source timestamps. Missing checks do not count as passed. An empty result produces no LINE message. Alerts cover the board's Top 10, drawn from the whole-catalog ranking; they do not claim a fresh quote scan of every listed security.

Each new alert is a five-stock Thai briefing: newly qualified instruments first, then ranked equities for context, with ETFs used only when needed and labelled explicitly. If fewer than five valid instruments exist, the report shows the actual count. A watchlist instrument is never labelled as a confirmed entry. At most five new signals trigger one delivery; additional new signals remain eligible for the next run. Each symbol triggers at most once per New York market date, while context stocks may reappear in later reports.

One LINE push contains a one-page PNG plus detailed Thai text. It shows business, source quote time, score, situation versus entry zone, stop, target, current reward/risk, upside/downside percentages, numeric fundamentals, dated news links, and remaining entry checks. A short glossary explains the terms and position sizing. Generic guarantee/disclaimer sentences are omitted; specific missing data and company risks remain visible. Monthly quota is checked before sending. Multiple message objects in one push count as one delivery to this one recipient.

News is fetched once per selected stock through the existing bounded Yahoo Finance adapter. A transport or response-format failure can use one bounded public Yahoo RSS request; authentication denials, rate limits and explicit bot blocks stop retrieval. RSS requests have a ten-second timeout, a one-MiB response cap, no authentication, and at most one validated redirect to a canonical RSS path on finance.yahoo.com or feeds.finance.yahoo.com within the original time budget. Company relevance and source timestamps are validated; requesting a ticker-specific feed alone does not establish company relevance. News within seven days is preferred; older context is labelled and expires after thirty days. Separately reviewed primary-source Thai summaries in `stock_alert_news.json` expire seven days after review. Provider headlines are displayed as attributed source context with topic-specific conditional implications, not invented verified positive/negative findings. Feed errors remain unknown, with sanitized diagnostic codes retained in the report metadata. News never silently overrides the entry policy. `Check stock briefing news feeds` tests the live feed without LINE credentials or message delivery.

Images and public report facts are published on `line-alert-media`, separate from application code. LINE receives immutable commit URLs; both PNGs must be publicly readable with the expected content type and exact bytes before the send is reserved. Rendering uses Pillow/RAQM and Noto Sans Thai. Runtime report files are retained as GitHub workflow artifacts for seven days. The media and state branches contain no recipient IDs, tokens, personal balances or private account data.

## Configuration

Repository Actions Secrets: `LINE_CHANNEL_ACCESS_TOKEN` and `LINE_USER_ID`. The built-in `GITHUB_TOKEN` writes delivery state and public report media to their separate branches. The sender verifies the token's bot basic ID against `@618mpszx` and checks that the configured recipient is accessible. Add the OA as a friend before the setup test. No webhook, friend-list read, personal chat access, broker login, or channel secret is needed.

Run manually with `mode=test` for the one-time setup message, `mode=dry-run` to count current signals without sending, `mode=scan` for normal delivery, or `mode=preview` for the one-time requested five-stock format example. Preview reports use real timestamped market data and can contain watchlist-only stocks; they do not change the automated trigger. `Preview LINE five-stock report` sends that requested example when its workflow is installed on main, with a durable once-only key. A successful LINE API response means LINE accepted the request, not a read receipt.

## Delivery state and failures

The isolated `line-alert-state` branch stores HMAC identifiers and the pending public-market alert text. It never stores LINE IDs, tokens or account profiles. A durable reservation, exact message body and LINE retry UUID are saved before sending. Uncertain sends reuse that exact request within its expiry. Expired uncertain sends are suppressed for the same market date to avoid duplicate or stale notifications; the report exposes `expired_pending`. This intentionally favors avoiding stale/duplicate delivery over claiming guaranteed delivery.

Quota, permission, malformed-data and delivery failures are visible in Actions. Logs and summaries contain counts/status only, not credentials or recipient IDs. Tests use fake delivery and storage; they never call LINE. To pause alerts, disable `LINE stock alerts` in GitHub Actions; the dashboard/ranking jobs continue independently.
